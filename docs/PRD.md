# SmartNoteGen 产品需求文档（PRD）

> 版本：v1.0（简单 PRD）｜ 作者：许清楚（Product Manager）｜ 日期：2025-08-09
> 状态：待架构师评审

## 1. 项目信息

| 项 | 内容 |
|---|---|
| Language | 中文 |
| Programming Language | Python 3.12+（CLI 工具，本轮**不做 UI**） |
| Project Name | `smartnotegen` |
| 运行环境 | Windows 11 + NVIDIA RTX 4060（8GB VRAM，CUDA 可用），已有 venv（`D:\New\Music\SmartNoteGen`） |

### 1.1 原始需求复述

独立创作者希望用 AI + Python 在本地生成歌曲的**音乐旋律与器乐素材**（一个或几个乐器即可），产出物上传 **Suno Pro**（付费订阅）做最终风格化与歌曲合成（加人声、完整编曲）。

**关键事实约束（已确认）：**
- Suno 只接受 **WAV/MP3** 音频，**不接受 MIDI**；
- 上传片段最佳实践为 **10–30 秒纯器乐**、无强混响、无人声；
- Suno Pro 上传上限 8 分钟，支持 Melody Lock / Add Vocals / Add Instrumental 等二次动作。

**核心工作流：** 程序化生成 MIDI →（可选乐理驱动旋律优化）→ 渲染为 WAV → 导出为 Suno 合规片段 → 手动上传 Suno Pro 合成成品。

## 2. 产品定义

### 2.1 Product Goals（3 个正交目标）

1. **素材可生成**：用脚本 + music21 乐理规则在本地稳定产出多轨 MIDI（和弦进行、旋律、节奏），摆脱对在线工具的依赖。
2. **格式可衔接**：一键将 MIDI 渲染为 10–30s 纯器乐 WAV/MP3，参数符合 Suno Pro 上传规范，做到「本地产出即平台可消费」。
3. **能力可扩展**：预留 MusicGen / DiffRhythm 等 AI 模型集成位，在不推翻核心管线的前提下逐步增强编曲与草稿能力。

### 2.2 User Stories

1. **作为独立创作者**，我想输入和弦进行（如 `C-G-Am-F`）和风格参数，程序自动生成一段多轨 MIDI，以便快速获得旋律与器乐骨架。
2. **作为乐理学习者/创作者**，我想基于指定调式、BPM 和风格让 music21 生成旋律及变奏，以便在创作中获得有乐理依据的动机素材。
3. **作为 Suno 用户**，我想把生成的 MIDI 一键渲染成 10–30 秒纯器乐 WAV，以便直接上传 Suno Pro 用 Melody Lock / Add Instrumental 扩展成完整歌曲。
4. **作为批量创作者**，我想一次生成多个随机变体（不同和弦/节奏/风格组合），以便挑选最满意的动机上传。
5. **作为进阶用户**，我想（可选）调用 MusicGen / DiffRhythm 对旋律 WAV 做扩编曲或生成歌曲草稿，以便在本地预览完整听感。

## 3. 技术规范

### 3.1 Requirements Pool

#### P0（第一版必须，Must Have）

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-1 | **CLI 入口**：提供子命令式命令行工具（生成/渲染/导出），支持配置文件 | 运行 `smartnotegen --help` 可列出全部子命令；关键参数可通过 CLI 或配置文件覆盖 |
| P0-2 | **程序化 MIDI 生成**：脚本化生成多轨 MIDI（和弦进行、旋律、节奏、多轨/多乐器） | 给定和弦进行与 BPM 可输出标准 `.mid` 文件，至少含 3 轨（如和弦/旋律/贝斯或鼓） |
| P0-3 | **music21 乐理驱动旋律生成**：基于调式/和弦进行/风格生成旋律与变奏 | 输入调式 + 和弦进行可生成符合乐理约束（音阶内音符、目标音对齐）的旋律；支持至少 1 种变奏方式 |
| P0-4 | **MIDI → WAV 渲染**：FluidSynth + SoundFont 方案 | `.mid` 可渲染为 WAV，音色随 MIDI 乐器通道映射正确，无爆音/明显失真 |
| P0-5 | **Suno 合规导出**：导出 10–30s 纯器乐片段，格式/参数合规 | 输出 WAV（或 MP3），时长可控制在 10–30s 区间；无歌词、无强混响；采样率/位深符合主流上传要求（默认 44.1kHz/16bit，可配置） |
| P0-6 | **项目配置**：SoundFont 路径、输出目录、默认参数等集中配置 | 提供默认配置文件模板，缺失时有合理默认值，路径可被 CLI 覆盖 |

#### P1（第二版应有，Should Have）

| ID | 需求 | 说明 |
|---|---|---|
| P1-1 | **MusicGen 集成（melody conditioning）** | 用旋律 WAV 作为条件输入，扩编曲/生成器乐伴奏；评估模型下载与推理耗时 |
| P1-2 | **DiffRhythm 集成（完整歌曲草稿）** | 生成带人声草稿；**需评估 RTX 4060 8GB 显存可行性**（显存不足时提供 CPU/降采样回退或明确不可用提示） |
| P1-3 | **批量生成/随机化** | 对和弦进行、节奏型、风格做随机组合，一次产出 N 个变体；支持随机种子保证可复现 |

#### P2（增强项，Nice to Have）

| ID | 需求 | 说明 |
|---|---|---|
| P2-1 | **DSP 参数调优** | 音量平衡、淡入淡出、轻度 EQ/压缩、可选混响控制，提升试听质感 |
| P2-2 | **更丰富乐理规则** | 声部进行约束（避免平行五度/八度）、对位、和弦转位、节奏型库扩展 |
| P2-3 | **工程化完善** | 日志分级、错误处理、单元测试、依赖锁定、打包脚本 |
| P2-4 | **预设风格库** | 内置流行/摇滚/电子/古典等风格预设（BPM、乐器、节奏型、旋律特性） |
| P2-5 | **输出管理** | 按项目/日期组织输出目录，自动命名，导出元数据清单 |

### 3.2 UI Design Draft（CLI 交互设计）

本轮无图形 UI，以 CLI 子命令组织，示意如下：

```
smartnotegen
├── generate midi    # P0-2：程序化 MIDI 生成
│     --chords "C-G-Am-F" --bpm 120 --bars 8 --style pop
├── generate melody  # P0-3：music21 乐理驱动旋律
│     --key "C major" --chords ... --variations 3
├── render           # P0-4：MIDI → WAV
│     --input xxx.mid --soundfont xxx.sf2
├── export suno      # P0-5：Suno 合规导出
│     --input xxx.wav --duration 25 --format wav|mp3
└── config           # P0-6：查看/生成配置
      --init
```

核心交互原则：
- 每个子命令默认参数合理，**零参数也能跑通一条 demo 管线**；
- 输出文件路径、SoundFont 等通过配置文件 + CLI 覆盖；
- 所有随机化操作支持 `--seed` 可复现。

### 3.3 Open Questions（待确认问题）

1. **交互方式**：是否需要交互式 MIDI 编辑/试听（如键盘输入音符、实时播放）？还是维持纯参数/命令行驱动即可？
2. **预览能力**：是否需要本地波形/频谱预览（如生成简单 HTML 预览页）？还是仅输出音频文件即可？
3. **SoundFont 选型偏好**：使用通用 GM 音色库（如 GeneralUser GS / FluidR3）即可，还是需要指定特定乐器的高质量音色库（会增大体积）？
4. **导出格式**：Suno 上传默认用 WAV 还是 MP3？采样率/位深是否固定 44.1kHz/16bit，还是需要 48kHz/24bit 选项？
5. **Suno 自动化**：是否需要自动上传 Suno（官方 API/第三方接口），还是仅本地导出文件后手动上传？
6. **AI 模型推理偏好**：MusicGen / DiffRhythm 是否接受 GPU 推理（占用显存、耗时较长），还是更看重不影响其他工作的 CPU 低优先级推理？
7. **风格范围**：旋律/编曲主要面向哪些流派（流行/摇滚/电子/古典/其他）？影响节奏型库与乐理规则设计。
8. **多轨规模**：默认生成几轨、哪些乐器组合（如 钢琴+贝斯+鼓 / 吉他+贝斯+鼓）？是否需要用户自定义轨道乐器映射？
9. **可复现性**：是否需要全局随机种子控制（同参数可复现同一结果）？默认开启还是可选？
10. **默认参数**：默认 BPM、调式、时长（小节数）、曲风是否有约定偏好？

## 4. 关键取舍说明

- **P0 聚焦「本地生成 → Suno 消费」闭环**：MIDI 生成、乐理旋律、渲染、合规导出四条能力缺一不可，构成最小可用版本；AI 模型（MusicGen/DiffRhythm）因显存与推理成本不确定，明确降为 P1 可选模块。
- **Suno 合规性前置**：导出环节内置时长（10–30s）、纯器乐、无强混响约束，避免用户产出「不可上传」的素材，是本产品区别于普通 MIDI 工具的核心价值。
- **CLI 优先**：本轮明确不做 UI，但 CLI 设计预留了子命令扩展位（`export`、`config`），为后续 Web 预览或 GUI 留接口。
- **显存风险显性化**：DiffRhythm 是否可跑在 8GB 显存上需在 P1 阶段先行验证（spike），如不可行则提供降级方案或文档说明，不阻塞 P0 交付。
